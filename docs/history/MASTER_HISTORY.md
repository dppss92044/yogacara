## 0. 使用說明

### 0.1 H 編號與 v1.xx 的區別

- **H 編號**＝全專案唯一的「歷史事件序號」，代表**事件的相對先後順序**，一經編定不重排、不重用。新事件只往後追加（H156…）。
- **v1.xx**＝當時**實際使用過的版本名稱**，照原樣保留。
- 兩者**不得混為一談**。同一個 v1.xx 可對應多個 H 事件（例如 v1.61 有兩個，分屬不同 AI 視窗）。
- 沒有正式版號的早期事件，版號欄只寫「無」或「待定」，**不補造 v1.xx**。需要對照時，僅在「備註」寫「史料推定約 v1.xx」並標明推定。
- H 編號順序的定序規則：
  1. 同一視窗內依該視窗史料的順序。
  2. 跨視窗依 git commit 時間（＝使用者部署時間）、Claude-CC 的交付時間、GPT／Claude-chat 史料明載的時間；
  3. 無法判斷先後者，採最合理位置並在「未確認」欄寫明「相對位置不確定」。
- 本文件各 H 編號的樣例（如使用者舉例 H083／H084）僅示意，**實際編號以本文件為準**。

### 0.3 證據等級

| 等級 | 意義 |
|---|---|
| **A** | 使用者原話逐字保留（史料明載） |
| **B** | 使用者要求的忠實摘要（原文已遺失，但史料保留了要點） |
| **C** | AI 當輪回報／說明檔（AI 自述，**不等於使用者驗收**） |
| **D** | Git 實證（commit、檔案內容、hash 一致性） |
| **E** | 工具／測試結果檔（repo 內 `*-results.json` 或史料列的測試） |
| **F** | 推定（由說明檔、補丁註解、版本摘要反推；原文遺失） |

一筆事件可標多個等級，例如「B＋C＋D」。**F 單獨出現者可信度最低。**

### 0.4 狀態標籤

- **主線**：內容進入 git 主線並成為後續基底。
- **死支線**：曾由某 AI 交付或建置，但**從未進入 git 主線**，也不是後續基底。
- **草稿**：有修改紀錄，但未完成交付。
- **接回**：某一視窗的成品被使用者上傳給另一視窗作為基底，使支線內容重新併入主線。
- **未部署**：有交付但 git 無對應 commit（內容由後一版的 commit 一併帶入，屬推論）。
- **非開發**：問答、部署教學、史料整理等，沒有程式修改。
- **要求未實作**：使用者提出，AI 未實作。

### 0.5 驗收標籤

- **無回饋**：史料中找不到使用者對該版的回應。
- **要求修改**：使用者後續指出具體問題（**不等於整版失敗**）。
- **不滿意／失敗**：使用者明確表示不滿意或失敗。
- **使用者確認**：使用者明確表示成功／很好／已上傳成功。
- **後續繼續**：使用者直接提新需求，未表態。

> 全專案**只有**以下兩處屬「使用者確認」：H010（Claude-chat A-10「很好」）與 H076（GPT E13「我成功上傳 github 了」）。其餘 AI 宣稱完成者，**一律尚無使用者驗收**。
